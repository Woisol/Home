更完美的字体合并教程

发表于2025-04-27|更新于2025-05-05|Knowledge
|浏览量:

1.0版

严格按照完美字体合并教程走，将Cascadia Code NF和玄冬行楷结合，可以得到本字体的初版XuandongCas Code NF。连字、NF等都很完美，但唯独

1.1

发现了fontforge-度量(网图好像是尺寸，根据位置判断吧)-设置宽度可以查看和修改字体宽度，
先是尝试改字体全字大小，但是发现Cascadia字体宽度2048和全字大小1200并不同
尝试将中文字体全字大小设成2400, 加入后可以得到1.1版本，但是中文调得太大了在预览中顶部被遮挡

1.2

继续尝试修改英文宽度
开始还不知道使用编码-紧凑可以只显示编码了的字符，全选不会处理未编码的位置，选择了开头的常见英文字符处理后合并
效果还不错，只除了连字部分宽度不合外其余都合适\

使用了紧凑视图并全选修改宽度以后就出现问题了()，比如

似乎只要修改Cascadia的字符宽度（并合并中文字符后）（全字大小似乎不影响）就会导致连字特性丢失……
修改Cas的全字大小同样会导致失效……
但是加大中文的全字又会导致顶部溢出……

retain kerninq infomation弹窗指的是保留字距信息，应该是没有影响且应该勾选的

参考网图修改生成字体的设置，使用原生Cas字体测试发现必须勾选OpenType选项不然原生也丢失连字特性，欣喜若狂在新字体中尝试，估计是修改了Cas字体宽度导致连字依然丢失
此时的情况是设置中字体的连字特性正常但是VSC中失效，比之前不勾选OpenType好点……
当然此时FontForge内连字都是正常的……

md真的不知道这一天在折腾个什么鬼

害所以不及时记录还是容易忘记太多……

突然考虑到最开始成功的版本中英文其实是很和谐的只是中英文稍微不对齐，再次考虑缩减Cas字体大小
结果依然是设置中正常但是VSC丢失连字
而且为什么中文不调大最终整体字体还是变大了？对不起艹VSC的字体类名太多了混了，但是连字依然丢失

尝试了一下fira，也是全字大小1950宽度1200不规范的，加上两次生成都闪退
放弃了……先用原来的吧

继续尝试，发现Regular加上现有的Xuandong_2048按照网图选项生成能够合成完美字体，
以及Light也能够合成
所以问题估计就在于宽度调整……

定位了……再次尝试light调宽度+Xuan_2048，正确失效……不是生成选项问题，不是_2048问题……

另外注意导入中文字体要取消紧凑不然合并失败

无法解决核心问题……回归1.1版本并改名XuanCasCodeNF，只将xuan全字增大到2048后手动拓展宽度到2400并调整部分半边符号边距。至少连字等正常了……
