如果尝试通过 KWIN_COMPOSITOR_MODE=1 或者 [Compositing] OpenGLIsUnsafe=true 强制启用 Compositor，进入了桌面也是一片黑无法使用。

另外此时如果通过 plasma-start-settings 打开一个窗口，会发现窗口的特效是生效了的。

再另外在本机骁龙 8 Elite 上，使用 Mesa 驱动并关闭 Compositor 时窗口透明部分会显示为纯黑，且画面会出现撕裂，应当属于正常现象。在本机上使用 kgsl 撕裂现象会稍微缓解。

关于 kgsl 和 zink

kgsl 更接近安卓原生的 GPU 驱动，zink 则是 OpenGL on Vulkan 的实现。

MESA_LOADER_DRIVER_OVERRIDE 的值：kgsl 是 Qualcomm 的 GPU 内核接口驱动，让 Mesa 通过 kgsl 直接与 GPU 通信；zink则是 Mesa 的 OpenGL-on-Vulkan 实现，Vulkan 路径。

不设 MESA_LOADER_DRIVER_OVERRIDE 驱动也是生效的，默认选择应当是 zink

Droidspace 介绍

README.md：

Droidspaces 是一个容器运行时，它利用 Linux 内核命名空间来运行完整的 Linux 发行版，并使用真实的初始化系统（systemd、OpenRC 等）作为 PID 1。

与仅改变表面根目录的传统 chroot 不同，Droidspaces 实现了真正的进程隔离。每个容器都拥有独立的 PID 树、独立的挂载表、独立的主机名、独立的 IPC 资源以及独立的 cgroup 层级。其结果是创造出一个完整的 Linux 环境，体验类似于轻量级虚拟机，但由于直接共享主机内核，因此完全没有性能开销。

Droidspaces 旨在原生兼容 Android 和 Linux 桌面系统。在 Android 上，它能处理所有内核差异、SELinux 冲突、复杂的网络场景以及加密问题，这些问题往往会导致其他容器工具无法运行。在 Linux 桌面上，它开箱即用，无需额外配置。

整个运行时是一个不到 260KB 的独立静态二进制文件，基于 musl libc 编译，没有任何外部依赖。

简单来说，更完善的进程隔离，支持 systemd，发行版更完整也意味着装软件（大概）不用之前 Termux 那么折腾了
以及 README 后面也提到实现了安全的 udev（妈妈再也不用担心我 Chromium 登录微软账号闪退了口牙）

前提

Droidspace 需要解锁 bl 并 root，如果你的设备无法 root，请出门左转 Termux Proot 容器，基础使用体验上是接近的……

使用

整体来说步骤ww

  1. 安装 Droidspace apk，自己在 Release/latest 下
  2. 编译内核，直到通过 app 内的内核检验
  3. 使用官方或其它的 rootfs 创建容器
  4. 底栏“面板”进入容器并以你的用户身份启动

更具体的步骤请参考 Goldbug 的酷安文章，下面仅补充一些自己遇到的问题

编译内核

这部分由于本人和作者本人用的同样设备，这里直接刷入作者提供的内核。作者本人也收集了其它设备的编译内核，具体自己看……

刷内核建议使用 Horizon Kernel Flasher。

创建容器

Droidspace 创建容器需要一个 rootfs，作者这里使用官方的 Ubuntu 镜像，在底栏 容器 tab 点击 + Float Action 按钮选择 .tar.gz 文件即可。
容器配置界面开启硬件加速和 termux-11 即可

你当然也可以使用 Goldbug 作者提供的 Arch / Debian 镜像，不过本人由于在 Ubuntu 的折腾经验更多且需要从之前 Termux 迁移过来，所以选择了 Ubuntu 镜像。

其它

本质安装兼旧 Proot 容器迁移过程中的其它问题

KSU overlayFS 不兼容

Droidspace 明确红字警告：与 KernelSU 的 overlayFS
不兼容，会导致卡循环。如果你用 Hybrid Mount 或者同类模块，建议将所有模块切回
Magisk Mount 后再使用 Droidspace。

符号链接失败

在安卓 sdcard（fat32）目录下执行 ln -s 会报 Function not implemented，这是
fat32 文件系统不支持符号链接导致的，需要把操作放在容器的 ext4 分区内。

KDE 中文显示方块

这是折腾最久的问题，原因是多方面的：

  1. 语言包没装全*：仅装 language-pack-kde-zh-hans 不够，还需要改 /etc/locale.gen
    取消 zh_CN.UTF-8 的注释，然后执行 locale-gen

  2. 字体权限问题（本次核心坑）：用 sudo cp 把字体拷到 /usr/share/fonts
    时，文件所有者是 root 且权限通常是 600，root
    运行的缓存生成器能看到字体并写入索引，但普通用户运行的 KDE/Qt
    程序没有读取权限，拿不到字形数据就直接画方块

  3. 对照之前正常运行的 Proot 安装字体包：

  4. 迁移时直接覆盖配置：从 Proot 迁移时覆盖 .local 和 .config
    才最终解决英文界面问题，说明语言设置更多藏在用户配置而非系统级别

Fcitx5 安装遗漏

装输入法时只装了 fcitx5-rime，漏了：

  • fcitx5-chinese-addons（有个 s，不是 fcitx5-chinese-addon）
  • kde-config-fcitx5（KDE 环境下的配置集成）

Flatpak 在容器中的坑

  • USTC 镜像源不稳定，flatpak search 网络错误却显示为 no match
    found，误导性极强
  • remote-modify 改源后无法恢复，需要 remote-delete 再重新 remote-add
  • system 级和 user 级配置容易混淆：不加 –user 默认配到 system，install 也走
    system 需要疯狂输密码
  • 最终建议：直接用 apt，别折腾 Flatpak

Chromium 是 Snap

Ubuntu 24.04 的 apt install chromium-browser 实际装的是 snap 版，之前的 Proot
配置不通用，相当于一个新实例。

Mesa 驱动与 KWin Compositor

详见上文「KDE 桌面及其特效」部分，这里补充完整的心路历程：

1.安装 Mesa + turnip 覆盖后，默认走
zink（OpenGL-on-Vulkan），透明不生效且画面撕裂
2. 切换到 kgsl 后撕裂缓解，但透明部分仍纯黑
3. 意外发现：之前调试时在 ~/.config/kwinrc 中设了 Enabled=false 关掉了
Compositing——这才是桌面特效不生效的真正原因
4. 重新开启 Compositing 后，在骁龙 8 Elite
上桌面特效确实能跑起来了（虽然卡开机）
5. 但尝试用 KWIN_COMPOSITOR_MODE=1 强制启用仍会黑屏
6. 在骁龙 8 Gen 2 上无论 kgsl 还是 zink 都跑不起来
7. 结论：当前 Mesa 驱动（截至 2026-04-22）无法稳定支撑 KWin
Compositor，关闭是必要的妥协

Termux-X11 刷新率

  • 不加 -fakescreenfps 参数时默认只有 50Hz，体验明显不跟手
  • 加上 -fakescreenfps 120 后效果立竿见影
  • 不过实际效果还取决于安卓系统的屏幕刷新率设置，确保系统也切换到了高刷模式

小彩蛋

KDE 桌面启动时，，如果背景已显示但底栏还没加载出来时，开 plasma-open-settings 看到的是英文界面 + 默认蓝色主题
